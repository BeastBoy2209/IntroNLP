## Дорожная карта (Roadmap)

- [x] **Неделя 1–4: Подготовительный этап**
  - Выбор темы "Automated Content Moderation".
  - Постановка проблемы ручной модерации сообщений и определение архитектуры пайплайна.
  - Утверждение стека технологий и состава команды (Тимур Харитонов, Даниал Каиров).

- [ ] **Неделя 5 (Текущая): Работа с данными и EDA**
  - Загрузка датасета Jigsaw Toxic Comment Classification с платформы Kaggle.
  - Разведочный анализ данных (EDA) и изучение распределения на основные классы: `Normal`, `Toxic`, `Spam`.
  - Разделение данных на обучающую (80%) и тестовую (20%) выборки.

- [ ] **Неделя 6: Предобработка текста**
  - Настройка пайплайна предобработки сырых текстовых сообщений:
    - Приведение к нижнему регистру (lowercasing).
    - Нормализация и токенизация.
    - Опциональная настройка обработки и фильтрации стоп-слов.

- [ ] **Неделя 7: Базовая модель (Baseline)**
  - Извлечение признаков с помощью алгоритма TF-IDF.
  - Обучение базовой модели Logistic Regression.

- [ ] **Неделя 8: Оценка качества baseline-модели**
  - Оценка качества с использованием метрик: Accuracy, Precision, Recall и F1-score.
  - Построение матрицы ошибок (Confusion matrix) для детального анализа ошибок классификации.

- [ ] **Неделя 9: Эксперименты с альтернативными моделями**
  - Обучение альтернативных моделей классификации (Naive Bayes, Linear SVM) для сравнения результатов.
  - Выбор итоговой модели с лучшим показателем F1-score (баланс между пропущенными токсичными сообщениями и ложными срабатываниями).

- [ ] **Неделя 10: Разработка веб-API**
  - Разработка веб-API на Python с использованием FastAPI.
  - Создание эндпоинта `POST /predict`, принимающего текст и возвращающего предсказанную метку класса (`label`) вместе с оценкой уверенности (`confidence`).

- [ ] **Неделя 11: Пользовательский интерфейс (UI)**
  - Создание интерактивного визуального интерфейса для демонстрации работы модели с использованием Streamlit.

- [ ] **Неделя 12: Интеграция с Telegram-ботом**
  - Интеграция API классификатора с Telegram-ботом для автоматического обнаружения токсичности и спама непосредственно в чатах.
  - Настройка платформенной логики принятия решений о блокировке или удалении сообщений на основе порога уверенности (`confidence`).

- [ ] **Неделя 13: Сквозное тестирование и планы развития**
  - Сквозное тестирование всего пайплайна на новых сообщениях.
  - Составление плана дальнейшего развития проекта (поддержка мультиязычности, учет контекста диалога, переход на архитектуры типа BERT).

- [ ] **Неделя 14: Финализация и защита**
  - Финализация проекта и подготовка к защите.
  - Подведение итогов работы и демонстрация эффективности решения (повышение безопасности онлайн-общения и снижение нагрузки на модераторов).
